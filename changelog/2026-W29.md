## Verification
- New "Lying Tests" section: a green suite that mocks the risky paths or swallows failures manufactures false confidence
- New rule: before trusting an existing suite as a safety net, verify it can actually fail — confirm it hits real risky paths and that a broken build turns red

## Context Engineering
- New rule: set the context handoff threshold in absolute tokens, not just a percentage — roughly 300-400K for a 1M-token model, ~100K for smaller ones
- Names the "dumb zone" degradation boundary and explains why a percentage hides window size
- New trajectory-poisoning signal: repeated "you're completely right!"-style capitulations mean start a fresh session instead of continuing to correct a poisoned one

## Team Adoption
- New section on availability shock: a June 2026 export-control order forced Anthropic to shut down Fable 5 and Mythos 5 globally overnight with no notice
- New rule: keep a second model provider genuinely runnable and periodically exercised, not merely configured, so an availability shock is a config switch rather than an emergency migration
- New rule: assign a single named human Directly Responsible Individual (DRI) accountable for outcomes — accountability cannot transfer to an agent

## Security and Threat Model
- New section: OpenAI's Patch the Planet program corroborates verifier-independence via a human gate — engineers manually review every finding before it reaches a maintainer
- New chapter section "Bounding Your Own Agents": frames a drifting agent as an insider attack that moves too fast for traditional incident-response timelines
- New four-question framework for granting agent access: untrusted inputs, permitted actions, blast radius, observability
- New rule: scope agents via the principle of least agency — remove capabilities like `delete` rather than prompting the model not to use them
- New rule: bound agent access around the model's future capability, illustrated by an internal agent that, after an intelligence-only upgrade, proactively pinged another agent for help mid-incident
- New "rug-pull" MCP supply-chain risk: servers that redefine their tools post-approval, plus a rule to check for runtime re-validation and gate first use with a registry allowlist
