## Harness Engineering
- New rule: pair a recurring-task skill with a scheduled improver skill that turns captured human feedback into a PR against the base skill — and never automate the merge
- Warp's issue-triage worked example added end to end: trigger, inner skill, feedback capture, improver-skill loop, human-reviewed PR

## Verification
- New rule: schedule ground-truth reconciliation for any agent memory store that drives continuity, re-deriving history from an external record on a fixed cadence
- Adds a case where `eslint-refiner`'s memory silently went stale for seven weeks while the workflow kept running and filing correct-looking issues, caught only by cross-checking GitHub
- Flags a new failure mode: treat any reconciliation count landing exactly on a round API page limit (e.g. 100) as unconfirmed, not complete

## Context Engineering
- New rule: for questions that are a count, ranking, or inventory across many files, push search/aggregation into an execution step and let the model see only the aggregate and artifact
- Adds Sourcegraph Deep Search's sandboxed-Lua "evaluator" tool as a non-MCP example of the same filter-before-context pattern already covered for programmatic tool calling
- Notes neither Sourcegraph's token/accuracy savings nor its output completeness are quantified — verify against a known-answer subset before trusting it

## Team Adoption
- New rule: split cross-repo PATs by direction (read on source, write only on targets) after flagging that gh-aw's own example page and pattern page recommend contradictory token scopes
- New rule: before adding another AI metric, define the accepted result and report value and full cost per accepted result, per Matt Wood's three-question framework
- Points to gh-aw's OpenTelemetry outcome attributes (`accepted`, `waste_rate`, `zero_touch_rate`, `median_resolution_sec`) as a ready-made source for cost-per-accepted-result reporting

## Security and Threat Model
- New rule: give sandboxed code capabilities (pre-scoped function references) instead of credentials, enforce hard CPU/memory/storage/timeout ceilings, and lock down the sandbox's own provisioning API as a separate control
- Adds a tested smolvm resource-limit config (`--cpus 1 --mem 512 --storage 3 --timeout 30s --unprivileged`) and flags that `--overlay` does not actually limit root filesystem writes
- Adds OpenAI's post-incident design requirement that no single compromised component can grant internet/network egress, plus its ~20% monitoring-overhead cost estimate
